# Alchemy survival — first playable specification

Status: playable prototype implemented as Athanor. The user decisions below are settled; numeric defaults and proposed content can change through playtesting.

## Agreed game

A mobile-first circular alchemy puzzle that runs as a static GitHub Pages web app and supports desktop play. Arrange ranked magical ingredients, insert catalysts into mirrored patterns, and make space through chain reactions.

- Endless survival with the same vessel for the entire run, including long runs spanning multiple saved sessions.
- Death only when the vessel settles above capacity. No bosses, combat, quotas, timers or forced run endings.
- Reactions earn Essence toward recurring reward drafts.
- All acquired relics stay for the run, with no equipped-slot limit. A new run starts a fresh build.
- Three consumable slots, one use per slot. On a full inventory, replace an item or decline the pickup.
- Consumables act before placement. A tap between ingredients commits immediately, including a fatal move; there is no placement preview, confirmation button or manual rescue window afterward.
- Between-run unlocks add relics and starting options, rather than permanent stat increases.

## First playable content

One survival mode, one initial vessel style, eight relics, three consumable types, next-three-piece forecast, recurring rewards, run statistics and save/resume. Vivid magical ingredients, animated placements, sequential pair absorption and smooth vessel rearrangement support immediate one-tap play. Programmatic previews remain available for agents.

Agent playtesting is an explicit requirement: provide seeded headless runs, replayable action traces, readable legal actions and previews, stable UI selectors, and an isolated browser automation interface that preserves normal player saves. See [agent playtesting](./agent-playtesting.md).

Initial relic set: Prismatic Lens, Twinned Phial, Resonant Bell, Glass Halo, Silver Tongs, Echo Urn, Blood Crucible and Phoenix Seal. Effects and charges are drafted in the [design brief](./research-and-design.md#proposed-relic-families).

Consumables: Solvent removes a chosen ordinary ingredient; Twin Draught copies a vessel ingredient's rank into the next ordinary draw; Catalyst Ampoule converts the current ordinary incoming ingredient into a catalyst. Target selection can be canceled without spending the item; a confirmed item action consumes it and is saved.

## Prototype defaults to test

- Capacity: 18 pieces. At exactly capacity the vessel is stable; a non-clearing addition can cause overflow. Resolve the full reaction before checking.
- First matching pair of rank `a` produces `a + 1`. For each further outer matched pair of rank `a` around product `c`, produce `max(c + 1, a + 2)`. Consume each physical piece at most once, including circular wraparound.
- An unmatched catalyst remains in the vessel and may react when a later insertion gives it equal ordinary neighbors. If several catalysts activate, use a stable order shared by preview and execution.
- Start with a small low-rank vessel. Ordinary draw ranks track progression within a bounded band; catalyst and extraction availability need tuning so long survival is possible without becoming automatic.
- One copy of each relic in the initial catalog. Owned relics stay active together. Exhausting the catalog changes future relic offers to consumables; it does not stop rewards.
- Deduct the earned threshold when creating its saved reward draft. Choosing or declining completes that draft; reopening or reloading cannot generate the same reward again. If fewer than three distinct eligible options exist, show the available choices.
- Suppress capacity-reducing relic offers that would immediately overfill the current vessel. Show the new capacity in any eligible offer.
- Earn one Essence per consumed pair, with an additional bonus for long chains. Reward thresholds and the consumable/relic mix are configurable; no placement count is required to earn a reward.
- Non-reactive extraction, consumable use, time spent and menu actions earn no Essence. Rewards generated by a fatal placement cannot rescue it.
- Relic-generated catalysts replace a future draw; they never create free repeated placements. Charge counters persist across rewards and reloads.

## Resolution and rewards

1. Player optionally uses consumables or charged relic actions. Update the forecast after each action.
2. Player taps an insertion gap or the space between ingredients to commit immediately. Keyboard users can select a gap with arrows and commit with Enter.
3. Resolve reactions and triggered effects in a deterministic order. Save the committed result immediately and animate recorded pair events in order. Block further actions until the short presentation settles.
4. Apply any equipped automatic overflow protection, then check capacity. If still above capacity, end the run.
5. If alive, award pending Essence and present any earned reward choices. Keep the vessel intact. Carry excess progress forward; handle multiple earned rewards sequentially.
6. Save the settled state and continue with the next piece. Animations must not permit duplicate inputs.

Agent previews use the same rules as execution without consuming charges, advancing randomness, granting rewards or changing saved state. Normal gameplay does not display a placement preview or ask for confirmation. Reduced-motion preferences skip movement effects. Reloading during a reaction restores the committed result without replaying or losing an action.

Resolve competing relic effects in acquisition order. Bind future-draw replacements to specific draw identities; once a draw has a pending replacement, defer a conflicting replacement to the next eligible ordinary draw rather than silently discarding either effect. Preview and save data include modified draws, charges, pending effects and used automatic protection. This ordering is an initial implementation default to validate through playtesting.

## Between runs

Track best survival, highest ingredient and discoveries. Provide a small unlock path: demonstrate the loop with a new relic option unlocked by a discovery or survival milestone, and a starting-vessel option unlocked later. Exact achievements are tuning content. Save unlocked options independently of the current run; unlocks add choice without automatically increasing starting power.

## Mobile and desktop

- Portrait-first vessel with large insertion targets, visible incoming piece, capacity, forecast and three accessible consumable slots.
- Tap a gap or between ingredients to place directly. Support touch and mouse, with no hover-only controls or confirmation step.
- Magical symbols, numeric ranks and color together; reduced-motion support and skippable/fast reactions.
- Static assets work under a GitHub Pages repository subpath; no backend or account is required.
- Save after every confirmed state mutation, including consumable/relic use and reward selection. Preserve a pending reward and deterministic future draws across reloads.

## Verification before handoff

Verify circular wraparound, chain arithmetic and termination, dormant catalyst activation, preview/execution agreement, overflow after full resolution, consumable targeting/canceling, full-inventory choices, relic ordering, reward thresholds and carryover, duplicate reward protection, and save/resume with identical future draws. Exercise long seeded runs with all relics active to find repeating automatic-survival engines.

Check small portrait and desktop layouts, touch/mouse input cancellation, rapid duplicate input, reduced motion, refresh after an item use or while choosing a reward, and asset paths under a project subdirectory.
